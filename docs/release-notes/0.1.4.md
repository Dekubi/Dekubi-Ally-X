# Dekubi X 0.1.4 (2026-11-25)

## Why
In play the owner saw worse graphics than Gemini's build. Logs, same title:
- Gemini's build (09:48): 2.7 to 3.5 fps, 0 pipelines being made, 1 indirect draw dropped.
- 0.1.3 (11:26): 1.1 to 1.9 fps, 269 pipelines being made, 203 indirect draws dropped.

Gemini's launcher set `RELAY=2`, `LEVELS_ON_DEMAND=1`, `PIPELINE_WAIT_MS=24`
and warmed the shader cache before launch. The 0.1.1 move to victory-fork
replaced Gemini's `main.rs`, `translate.rs` and `logging.rs`, so none of it ran.

## Restored from Gemini's build (`_backup-gemini-2026-11-25`)
- `apps/dekubi-ally/src/main.rs`: no-argument launch, title discovery by
  `MicrosoftGame.Config`, per-launch log, error dialog, console attach,
  default env settings (now also for `run --execute`), auto warm-up (also for
  `run --execute`; `DEKUBI_AUTO_WARM=0` skips it).
- `apps/dekubi-ally/src/translate.rs`: `warm_for_launch`, host GPU probe, `translate --cache`.
- `crates/ally-core/src/logging.rs`: `launch_log_dir`, `launch_log_path`, `init_with_file`.

Notes, `Dekubi X.exe` name, upstream fixes, autopad.
