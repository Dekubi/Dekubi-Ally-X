# Dekubi X 0.1.11 (2026-11-25)

Hand port of VIctory-Belobug-AMD ccab973, 918ab03, afca189, 76387c2 (GPL-3.0-or-later,
beloooo) onto this tree's list parts (victory-fork's cut-at-wait `earlier`/`gate`):

- `crate::list::hoist`: before an indirect draw/mesh dispatch, unless the list's open
  clamps part still stands (no dispatch or buffer copy since), the recording is cut:
  the part so far, then a part for clamps, then a new host list with the state replayed.
  `end_hoist` closes the clamps part (clamp_end barrier) at the next cut, close, reset or
  submission.
- `HostList::{count_write, writes, clamp_room, clamp_end}`, `ClampChunks` (256 KiB
  buffers; states reset to common on reset, as buffers decay after a submission).
- `crate::indirect::{hoist_mode, hoisting, bound_before, HOISTED}`; modes 0, 1, 7
  (default 7: a UAV barrier between clamps). Only with `crate::queue::cuts()`.
- `State::execute_indirect` takes the open clamps part; windows, dispatches and
  rectangle lists keep the inline clamp.
- Not taken from Belobug: modes 2-6 (fault finding), GPU time per kind of command.

Unverified on hardware: clippy -D warnings clean for x86_64-pc-windows-msvc.
