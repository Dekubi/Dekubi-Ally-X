# Dekubi X 0.1.12

## Changes

- `DEKUBI_MERGE_RUNS=8192` by default (was 512). In the 0.1.11 run on the
  RTX 5060 (log 2026-11-25 13:27) the settles for title bytes under flights'
  shader writes took 119.4 ms a frame of the title's threads while the
  submitting thread waited 160 ms a frame for the card, which stood idle
  42 ms a frame behind us. The cap made a submission settle the flights
  instead of sending more changed runs to card copies.
- New log line beside "title bytes put in under flights' shader writes":
  why a merge still asked for a settle (not write-watched, writes unknown,
  card copy past the runs left, no snapshot), since the start.
- Progress window (`apps/dekubi-ally/src/progress.rs`) during the launch
  shader warm-up: containers found, translated, cached; seconds so far.
  `DEKUBI_PROGRESS_WINDOW=0` hides it.

## Diagnosis of the 0.1.11 "missing areas" report

- Texture work per frame equal to 0.1.9 (10.7 ms, 31 MB; about 380 slots due).
- 3,000-6,000 index-picked texture slots wait for title memory to be mapped
  (the title's own streaming), and the card was past its budget
  (7.6 GB in use against 6.2-7.1 GB), so new texture copies waited for room.
- The ~460 draws dropped a frame are pipelines with no host pipeline and
  none being made (shaders that do not translate), not late ones.
